# 主界面播放列表列自定义改造方案

## 1. 背景与目标

当前主界面播放列表使用 `CPlayListCtrl` 显示数据，列定义和列顺序都是固定的：

- 序号
- 曲目
- 时长

现状存在以下限制：

- 用户无法增加独立列，例如专辑、歌手、文件名、路径。
- 用户无法隐藏现有列，例如隐藏时长。
- 用户无法调整列顺序，例如把专辑移动到歌手前面。
- 当前列表资源样式关闭了表头，无法通过表头完成列管理。
- 播放列表显示格式目前仅支持“单列文本格式切换”，不支持真正的多列自定义。

本次改造的目标是：

1. 在主界面播放列表中启用表头。
2. 用户可直接在主界面通过表头右键菜单选择显示哪些列。
3. 用户可通过拖拽表头调整列顺序。
4. 用户偏好可持久化保存，并在下次启动时自动恢复。
5. 主界面、浮动播放列表、迷你模式播放列表尽量复用同一套列配置。


## 2. 推荐方案

推荐采用“主界面表头直改”方案，而不是先把设置入口放到选项设置对话框。

推荐原因：

- 交互路径最短，用户就在当前列表上完成操作。
- 与 Windows 列表控件的使用习惯一致。
- 该工程已存在带表头的列表与表头交互实现，技术路径明确。
- 配置持久化机制已存在，新增几项配置即可接入。
- 比单独增加设置页更符合此需求的即时性。

设置界面方案可以作为补充方案，例如后续增加“恢复默认列”或“高级列设置”，但不建议作为第一版主入口。


## 3. 现有实现定位

### 3.1 主界面播放列表

- 资源定义：`MusicPlayer2/MusicPlayer2.rc`
- 主窗口控件成员：`MusicPlayer2/MusicPlayerDlg.h`
- 主窗口刷新入口：`MusicPlayer2/MusicPlayerDlg.cpp` 中 `CMusicPlayerDlg::ShowPlayList`
- 播放列表专用控件：`MusicPlayer2/PlayListCtrl.h` / `MusicPlayer2/PlayListCtrl.cpp`

当前关键事实：

- 播放列表资源使用了 `LVS_NOCOLUMNHEADER`，表头默认不显示。
- `CPlayListCtrl::PreSubclassWindow()` 内固定插入 3 列。
- `CPlayListCtrl::ShowPlaylist()` 内按固定列序组装 `m_list_data`。
- 搜索状态选中项解析、提示信息等逻辑默认依赖固定列位置。

### 3.2 相关复用位置

`CPlayListCtrl` 不只用于主界面，还用于：

- 浮动播放列表：`MusicPlayer2/CFloatPlaylistDlg.cpp`
- 迷你模式播放列表：`MusicPlayer2/MiniModeDlg.cpp`

因此，若在 `CPlayListCtrl` 中完成列配置化，通常可以一并覆盖以上场景。

### 3.3 现有配置持久化

主程序配置主要由 `CMusicPlayerDlg::SaveConfig()` / `LoadConfig()` 读写 ini。

目前已有与播放列表相关的配置：

- `playlist_display_format`
- `playlist_item_height`

因此，新列配置建议继续写入同一份配置文件，避免引入新的配置载体。


## 4. 设计原则

### 4.1 第一版只改主界面播放列表

虽然媒体库中的“播放列表”标签页也有歌曲列表，但它的职责和展示模型不同。第一版只改主界面播放列表相关功能，避免范围过大。

### 4.2 兼容现有显示逻辑

当前存在 `display_format`，用于决定“曲目”单列文本如何显示。新方案不建议直接删除它，而是：

- 对主界面播放列表新增真正的“列配置”体系。
- 保留 `display_format`，用于兼容旧配置或仍需要单列文本显示的场景。

### 4.3 配置驱动，而不是硬编码列索引

后续所有与列相关的逻辑都应从“列 ID”出发，而不是假设：

- 第 0 列一定是序号
- 第 1 列一定是曲目
- 第 2 列一定是时长

否则一旦允许隐藏列或调整顺序，就会出现行为错误。


## 5. 建议的数据结构

建议新增一套播放列表列配置模型。

### 5.1 列标识枚举

建议新增枚举，例如：

```cpp
enum class PlaylistColumnId
{
    Index,
    Title,
    Artist,
    Album,
    Duration,
    FileName,
    Path,
};
```

第一版建议支持这些列即可，不要一次加入过多冷门列。

### 5.2 列定义结构

```cpp
struct PlaylistColumnDef
{
    PlaylistColumnId id;
    UINT title_text_id;
    int default_width;
    bool default_visible;
    bool allow_hide;
};
```

说明：

- `title_text_id` 用于接入现有多语言文本表。
- `default_width` 用于首次启动或恢复默认。
- `default_visible` 定义默认显示列。
- `allow_hide` 建议对主信息列做保护，例如标题列不可全部隐藏。

### 5.3 用户配置结构

```cpp
struct PlaylistColumnLayout
{
    std::vector<PlaylistColumnId> visible_columns;
    std::map<PlaylistColumnId, int> column_widths;
};
```

说明：

- `visible_columns` 同时承担“显示列集合”和“显示顺序”两种职责。
- `column_widths` 保存每列宽度，提升用户体验。

如果后续需要保留隐藏列顺序，也可以拆成：

- `column_order`
- `hidden_columns`

但第一版没有必要复杂化。


## 6. UI 方案

### 6.1 表头显示

需要移除播放列表资源中的 `LVS_NOCOLUMNHEADER`，使表头可见。

### 6.2 表头右键菜单

用户右键点击表头时弹出菜单，菜单内容建议如下：

- [x] 序号
- [x] 标题
- [x] 歌手
- [x] 专辑
- [x] 时长
- [ ] 文件名
- [ ] 路径
- 分隔线
- 恢复默认列

交互要求：

- 已显示列前带勾选标记。
- 点击后立即刷新列表。
- 至少保留一个主信息列，避免用户把所有内容列都隐藏。
- 若序号列被隐藏，相关逻辑不能再依赖第 0 列文本取真实索引。

### 6.3 拖拽调整顺序

建议启用表头拖拽换序。

交互要求：

- 用户拖动表头调整列顺序后立即生效。
- 新顺序在刷新列表或重启程序后应保持一致。
- 浮动播放列表和迷你模式若共用同一配置，也应同步顺序。

### 6.4 列宽调整

建议顺带支持手动调整列宽并保存。

原因：

- 一旦增加专辑、路径等列，默认宽度通常不够。
- 不保存列宽会影响实际可用性。


## 7. 配置持久化方案

建议继续使用现有 ini 配置。

### 7.1 建议新增配置项

可新增以下键：

- `playlist_columns_visible`
- `playlist_columns_width`

推荐格式：

- `playlist_columns_visible=Index,Title,Artist,Album,Duration`
- `playlist_columns_width=Index:48,Title:220,Artist:140,Album:180,Duration:70`

若希望避免字符串解析，也可以使用整数枚举值保存，但可读性较差。

### 7.2 默认值

若配置不存在，则采用默认布局，例如：

- 序号
- 标题
- 歌手
- 时长

也可以在首次迁移时根据旧 `playlist_display_format` 推导默认布局，但这不是必须项。

### 7.3 配置恢复失败的兜底策略

当读取配置失败或发现列 ID 非法时：

- 忽略非法列
- 如果结果为空，则回退到默认布局
- 对缺失宽度的列使用默认宽度


## 8. 代码改造清单

以下清单按推荐实施顺序排列。

### 8.1 第一阶段：建立列模型

目标：把当前“固定 3 列”改为“可配置列”。

改造项：

1. 在合适位置新增 `PlaylistColumnId`、列定义、布局结构。
2. 为 `CPlayListCtrl` 增加“当前列布局”成员。
3. 增加根据列 ID 取标题文本、取默认宽度、取单元格文本的辅助函数。
4. 增加一个“真实歌曲索引”获取函数，彻底替代依赖序号列文本的做法。

建议优先修改文件：

- `MusicPlayer2/PlayListCtrl.h`
- `MusicPlayer2/PlayListCtrl.cpp`

### 8.2 第二阶段：动态建列与动态填充数据

目标：列表展示逻辑完全由列布局驱动。

改造项：

1. 修改 `PreSubclassWindow()`，不再硬编码插入 3 列。
2. 增加重建表头的方法，例如 `RebuildColumns()`。
3. 修改 `ShowPlaylist()`，按当前显示列动态生成每一行数据。
4. 修改 `AdjustColumnWidth()`，支持按当前显示列设置宽度。
5. 修改鼠标提示逻辑，避免假设第 1 列一定是曲目文本。

关键注意点：

- 搜索状态下的高亮索引计算仍需正确。
- 无论是否显示序号列，都必须能正确定位到原始歌曲。

### 8.3 第三阶段：表头交互

目标：让用户可在主界面直接调整列显示与顺序。

改造项：

1. 去掉资源中的 `LVS_NOCOLUMNHEADER`。
2. 为 `CPlayListCtrl` 或其宿主窗口增加表头右键处理。
3. 在表头右键菜单中列出所有可显示列。
4. 点击菜单项后更新列布局并刷新列表。
5. 增加“恢复默认列”菜单项。
6. 支持表头拖拽换序。
7. 在列顺序变化后及时保存新顺序。

建议优先在 `CPlayListCtrl` 内部处理表头相关行为，减少主窗口耦合。

### 8.4 第四阶段：配置持久化

目标：用户偏好在重启后保持不变。

改造项：

1. 在配置结构中加入播放列表列布局字段。
2. 在 `LoadConfig()` 中读取列布局。
3. 在 `SaveConfig()` 中保存列布局。
4. 启动时将配置应用到 `CPlayListCtrl`。
5. 用户调整列显示、顺序、宽度后，更新内存配置。

建议优先修改文件：

- `MusicPlayer2/CommonData.h`
- `MusicPlayer2/MusicPlayerDlg.cpp`

### 8.5 第五阶段：复用场景收口

目标：保证主界面、浮动播放列表、迷你模式行为一致。

改造项：

1. 确认 `CFloatPlaylistDlg` 使用新列布局后显示正常。
2. 确认 `CMiniModeDlg` 使用新列布局后显示正常。
3. 如迷你模式空间太小，可为其设置单独的默认布局，但仍建议共享同一套数据结构。

## 10. 实施建议

建议按以下顺序开发，而不是一次性大改。

### 第一步

先把主界面播放列表从固定 3 列改成“固定但可重建的多列”，暂时不做右键菜单与持久化。

目标：

- 先验证新列模型是否稳定。
- 先让专辑列可以显示出来。
- 先解决搜索、高亮、提示对动态列的兼容。

### 第二步

加入表头右键菜单和列显示切换。

目标：

- 确认显示隐藏列行为稳定。
- 确认至少一列保底规则有效。

### 第三步

加入列顺序拖拽与持久化。

目标：

- 确认配置读写格式合理。
- 确认主界面、浮动播放列表、迷你模式一致。

这种分阶段方式最容易排查问题，也便于每一步单独验证。


## 11. 风险点与注意事项

### 11.1 当前选中项解析依赖序号列

这是第一优先级风险点。只要允许隐藏序号列，这块逻辑就必须重写，不能继续通过读取第 0 列文本反推歌曲索引。

### 11.2 搜索状态与高亮状态的映射

当前搜索结果、高亮项、提示信息的索引换算是建立在旧列模型上的。改为动态列后，要确保：

- 当前播放高亮正确
- 搜索结果选中正确
- 双击播放正确
- 右键菜单操作对象正确

### 11.3 浮动播放列表与迷你模式兼容

由于这两个窗口复用了 `CPlayListCtrl`，主界面改好后不能只验证主窗口，还必须验证这两个场景。

### 11.4 窄窗口布局

列数变多后，窄窗口下可能出现：

- 关键列被压缩得过窄
- 水平滚动体验差

建议为标题列保留合理最小宽度，并在默认布局中控制列数量。


## 12. 第一版建议范围

为了控制复杂度，第一版建议只支持以下能力：

1. 显示表头
2. 右键表头显示/隐藏列
3. 拖拽调整列顺序
4. 保存列顺序与列宽
5. 支持这些列：序号、标题、歌手、专辑、时长、文件名、路径

第一版暂不建议加入：

- 按列排序
- 更复杂的列模板系统
- 单独的设置页高级编辑器
- 与媒体库播放列表共用同一套列配置

开发完成后，至少验证以下场景：

- 默认列顺序正确
- 增加专辑列后数据正确显示
- 隐藏时长列后列表正常显示

### 13.2 表头交互

- 右键表头菜单能正常弹出
- 勾选列后立即显示
- 取消勾选列后立即隐藏
- 恢复默认列可正常工作
- 拖拽调整顺序后界面立即刷新

### 13.3 功能正确性

- 单击选中正常
- 多选正常
- 双击播放正常
- 搜索状态下选中、播放、右键菜单正常
- 当前播放高亮正常
- 鼠标提示内容正常

### 13.4 场景兼容

- 主界面正常
- 浮动播放列表正常
- 迷你模式正常

### 13.5 持久化

- 重启后列显示偏好保持
- 重启后列顺序保持
- 重启后列宽保持
- 配置损坏时能回退到默认值


## 14. 后续可扩展方向

如果第一版落地稳定，后续可以考虑：

1. 媒体库“播放列表”标签页也支持可配置列。
2. 增加“按列排序”能力。
3. 增加列模板，例如“精简模式”“详细模式”。
4. 在设置界面增加“重置播放列表列配置”入口。


## 15. 最终建议结论

本功能值得做，且优先建议在主界面直接实现，不建议先绕到设置页。

推荐落地顺序：

1. 先把 `CPlayListCtrl` 改造成配置驱动列模型。
2. 再加表头显示与表头右键菜单。
3. 再加列顺序拖拽和配置持久化。
4. 最后验证浮动播放列表与迷你模式。

按上述方式推进，风险可控，代码影响面也相对集中，适合作为后续开发参考文档。
